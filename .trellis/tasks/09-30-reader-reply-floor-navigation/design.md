# R4：显示全部定位原回复设计

## 目标与语义

用户已明确认可：我的回复 → 某条回复 → 显示全部，打开完整主题并尽量定位该回复。查询 pid/author/search 决定过滤窗口，导航目标 pid/floor 是独立元数据，二者不能混用。

## 启动与定位

1. 从已接收的当前回复数据取得合法 resolvedTid、目标 pid，以及存在时可信的全局 floor。匿名/缺少作者信息不影响有效 pid 定位；不得靠搜索页码或 pid 算术推断楼层。
2. ArticleNavigation.showAll 构建 FULL 查询，清空原查询 pid/authorId/searchPost；另传目标 pid/floor。已有无目标的显示全部仍从第一页打开。
3. 新阅读器初始使用普通源，普通源已约定每页 20 楼。存在可靠全局楼层时可据目标源的这一契约估算起始页；不能将旧 App 查询的窗口长度或搜索页当作目的分页大小。无可靠楼层时保持可读主题，并依现有有界查找能力处理，不无限扫描。
4. 将目标作为新 generation 的 ArticleAnchor 初始化；数据加载后匹配实际 pid，缺 pid 才使用真实 floor，找到后滚动并消费一次。目标不是 adapter index，不能跳到同数值但不同 pid 的行。
5. 若普通源切到兼容源，复用已验证的源页大小/现有至多一次对齐机制。页大小不明、目标删除或有界对齐找不到时保留已加载主题，并说明未能定位。

## 生命周期与共享文件

旋转、onNewIntent、刷新、缓存/源变更和账号变化遵守 reader generation 校验；迟到回调不能滚动新页面。启动目标不能使保存的离线页新增网络查询。
本任务不依赖搁置的 R7 修复。与 R2 的 Fragment、R1 的 Activity 参数、R3 的 Presenter 改动顺序集成。

## 验证与回退

使用纯导航/会话测试验证第一页、后续页、正常20楼与兼容不同页大小、PID-only/缺楼层、已删除目标、错误身份、源切换及过期锚点；所有定位必须落到实际匹配行。
回退仅去除独立目标 metadata 与定位行为，保留 FULL 查询语义；不得恢复为携带 query pid 的局部窗口。
