# 修复系统导航栏与深色模式显示

## Goal

修复 Android 系统导航栏与应用主题不一致，以及深色模式下设置组件文字和滑条配色不可读的问题；同时查明上一轮 issue2 修复的实际作用与失效原因，避免再次只修复表象。

## Background

- 用户提供的 Android 15 截图显示：论坛列表使用浅黄色应用背景时，底部系统导航区域仍为白色。
- issue5 反馈：深色模式下“屏蔽规则”页面的“新增”入口不可见；用户明确期望该入口在暗色模式下显示为白色，而不是把灰色辅助说明统一改为主题文字色。
- issue5 反馈：“字体和头像大小”页面的滑条在深色模式下配色不正确，期望已完成部分为白色、未完成部分为灰色。
- Git 历史存在与这些问题相关的提交，当前分支之后又执行过基线回退；需要对比当前代码与历史修复后确认根因。

## Confirmed Evidence

- 当前 `BaseActivity.java:56-63` 仍只在 `isNightMode() && !mComposeEnabled` 时设置导航栏颜色；`MainActivity.java:29-32` 在进入父类前将 Compose 标记设为 true，因此截图对应路径不会执行该设置。
- 2019 提交 `e2f46b4a` 将原本无条件的导航栏颜色改为仅夜间；2025 提交 `a428fc10` 又增加 `!mComposeEnabled` 条件。
- 2026-08-15 的 `43520b6d` 曾修改 Java BaseActivity、Kotlin BaseActivity 和 Compose `ScaffoldApp`，但 `571ad83d` 与 `54d16af7` 随后将这些源代码改动回退；所以当前分支实际上没有这次 issue2 修复。
- `FilterWordFragment.kt` 的外层使用 Material 2 `AppTheme`，但“新增”图标/文字和规则列表文字导入 Material 3 `Icon` / `Text`；这组默认内容色没有继承 Material 2 暗色主题，因此会在深色背景上落为不可读的黑色。`FilterWordFragment.kt:85,91` 的两处辅助说明显式使用 `Color.Gray`，不属于相同故障机制。
- 历史提交 `b9a7d2d9` 曾把两处灰色辅助说明改为资源 `text_color`，没有修复 Material 2/3 默认内容色断层；`24fd95f1` 曾将滑条已完成轨道改为 `@color/text_color`，两者随后均被 `571ad83d` 回退。

## Requirements

- R1：系统导航栏背景必须随当前应用主题背景变化，不能在 Android 15 浅色主题下显示为突兀白色。
- R2：分析并记录上一轮 issue2 修复修改了什么，以及其在当前版本无效的直接原因：修复提交已被后续基线回退，且旧逻辑本身只覆盖夜间/非 Compose。
- R3：深色模式下，“屏蔽规则”页面的“新增”图标和文字必须显示为白色；同样依赖错误 Material 3 默认内容色的规则列表文字不得保持黑色。保留“长按子项可删除”和规则说明的灰色辅助层级。
- R4：深色模式下，“字体和头像大小”页面的滑条左侧使用白色，右侧使用灰色；相关标签与数值文字保持可读。
- R5：保持浅色模式现有视觉表现，除系统导航栏主题匹配修复外不做无关重设计。

## Acceptance Criteria

- [ ] AC1：Android 15 上使用浅色黄色主题浏览截图所示页面时，底部系统导航区域与应用主题背景匹配，不再呈白色断层。
- [ ] AC2：切换深色模式后，“屏蔽规则”页面“新增”图标/文字显示为白色，已有规则列表文字可辨认；两处辅助说明仍为灰色。
- [ ] AC3：切换深色模式后，“字体和头像大小”页面滑条左侧为白色、右侧为灰色，标签和数值可辨认。
- [ ] AC4：浅色模式相关页面无文字、控件或系统栏颜色回归。
- [ ] AC5：自动化检查或可重复的构建/测试通过，并记录 Android 版本兼容性验证方法。

## Out of Scope

- 全量重做应用主题系统或页面布局。
- 与 issue2、issue5 无关的功能修改。

## Open Questions

无。用户已确认同时修复“新增”入口和规则列表文字；灰色辅助说明保持不变。
