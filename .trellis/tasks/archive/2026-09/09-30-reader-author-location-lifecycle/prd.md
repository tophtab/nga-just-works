# 属地查询生命周期与失败流程

## Goal

解释完整属地查询流程，并保证离开帖子后不继续查询其剩余作者。

## Parent requirement

R2 in ../09-30-reader-access-location-navigation/prd.md. 本子任务可独立验收；产品规则已明确，本窗口仅规划，实施留待新会话。

## Confirmed facts

自动查询与 checkInfo.js 同接口。Subscription.close 仅清理无主排队项，在途请求保留；Page 没有 onStop。详细缓存与失败表见父任务证据。

## Requirements

1. 以整个帖子是否在前台控制查询，不能按单个翻页 Fragment 可见性取消同帖预加载。
2. 没有其他有效前台消费者时清除/暂停未发送工作并取消在途调用，终止回调前保留物理槽位。
3. 保留共享去重、缓存、429 暂停和 503/拒绝停止；用户已决定间隔改为终止回调后 200–500 ms 随机。取消不是作者失败，不写入失败缓存。
4. 用户已确认返回时自动恢复原在线帖子的剩余查询；不把离线缓存页升级为在线，不重置已使用的补试次数。
5. 用户已确认网络失败首次尝试失败后，移到队尾补试一次，每轮总计最多两次。解析失败与网络失败需区分。
6. 用户已确认第二次网络失败后只对该作者冷却 30 秒：到期不自动发起第三次，之后遇到新的有效在线需求才可重新查询。非网络失败不纳入队尾网络补试，原有缓存/停止策略保持。
7. 首次请求在仓库空闲、缓存恢复完成、无站点暂停且上次请求间隔已过时立即发送，不额外等待 200–500 ms。已有排队或未满间隔时等待其剩余时间；首次失败后的队尾补试也遵守同一间隔。

## Acceptance criteria

- [x] 关闭帖子后未发送调用数不再增长；在途取消无重复调用。
- [x] A/B 帖共享作者不会因其中一个退出被误取消。
- [x] 后台暂停、返回、旋转重建、迟到回调、账号变化与同帖预加载均遵守确认规则。
- [x] 不存在取消导致的作者失败冷却，缓存/停止规则无回归。
- [x] 第一次网络失败不阻塞其他作者，队尾最多补试一次；没有即时重试和无限入队。
- [x] 冷却时间经过本身不产生新请求；冷却内重复订阅不能重启该作者。

## Out of scope

适用父任务非目标；不改其他查询功能，不执行真实 NGA/设备操作。

## Dependencies and review

无待选产品规则；返回自动继续及30秒网络失败冷却均获用户选择。与 R4 共用 Fragment 时顺序集成；不依赖搁置的 R7。最终规划摘要审核后，另开会话实施。
