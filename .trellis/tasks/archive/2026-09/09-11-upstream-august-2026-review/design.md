# 调研设计：上游 8 月改动与当前 fork 对照

## 目标与边界

本任务交付提交解释与借鉴判断，不设计或实施一套新的客户端功能。研究输出围绕同一用户问题组织为一份总览和若干证据专题，不需要拆成独立实现子任务。

用户已同意创建调研任务并保存结论。产品移植、发布、联网验证及实际合并不在本轮范围；本任务保持 planning 记录，后续是否选取候选功能属于新的实施范围。

## 固定输入

- 原项目：Justwen/NGA-CLIENT-VER-OPEN-SOURCE。
- 远端 `master@cdad1abb`、`master_release@22ba3082`。
- 当前 fork 比较基线：`main@8284c703`；原始上游基线：`5d807617`。
- 日期范围：2026-08-01 00:00:00 至 2026-09-01 00:00:00（+08:00）。清单保存作者日期及提交日期；先后关系按 Git 历史和提交日期解释。
- 全部 18 个 SHA（release 16 + master 2）及变更路径存于 `research/commit-inventory.json`。跨分支重复用稳定 patch-id 证明。

## 分析方法

1. 将实际补丁与最终上游源码一起阅读，区分改动的引入时间、中间状态和最终行为。
2. 按具体用户行为而非提交标题对照 fork，区分已经独立修复、旧实现本就覆盖、仍有缺口、迁移后新出现的兼容问题。
3. 追踪模型、parser、HTML、页面、缓存、偏好和请求回退之间的调用顺序；必要时利用现有任务/规范解释本地定制边界。
4. 对决定采纳顺序的 JSON 默认行为，使用缓存 JAR、真实 DTO、完全合成输入做离线对照。
5. 所有建议附成本和验证条件；未测的上游运行效果、API 可用性、性能或包体变化不作为已确认收益。

## 输出与责任

- `research/overview.md`：用户可读总览、16 项清单、覆盖状态、采纳顺序。
- `research/branch-and-small-fixes.md`：分支关系、图床、jdata、图标、发版/SDK。
- `research/data-refactor.md`：七步数据重构、fastjson2 迁移、旧代码清理。
- `research/bugfix-browser.md`：750871b3 与 2becba2a 的子变化和完整调用链。
- `research/json-compatibility.md` 与 `research/probes/`：两组离线实验及可复现材料。

研究子代理只写分配给它们的专题文件。主会话负责 Git 操作、导出临时源码、实验、总览、交叉核对和任务记录。临时上游源码/完整补丁放在 `/tmp/nga-upstream-august-2026-review`，任务只保留持久证据和合成验证材料。

## 未来借鉴时必须保留的边界

- 本 fork 的完整页面附件前缀、手动图床优先级、历史缓存/头像旧域名归一化。
- 现有帖子预取、单页请求去重、后台失败静默与前台接管。
- 收藏的 fid+stid 稳定身份、原子顺序持久化、主页根节点及拖拽排序。
- 原始响应/本地存储兼容、明确错误与请求身份边界。
- 当前 Android 10 安装下限及独立的版本/签名/发布流程。

研究没有修改这些产品边界，也没有用上游实现反向覆盖既有规范。
